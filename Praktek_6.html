Login Sesi & Dashboard Profil

Studi kasus SharedPreferences: menyimpan sesi login, masuk otomatis ke dashboard profil, dan wajib login ulang bila data sesi tidak ada

🔒

Pendahuluan & Ketentuan

Pada praktikum ini Anda membangun aplikasi dua layar: Layar Login dan Dashboard Profil. Saat pengguna berhasil masuk, data sesinya ditulis ke SharedPreferences. Ketika aplikasi dibuka lagi, aplikasi memeriksa sesi itu lebih dulu — kalau ada, pengguna langsung masuk ke dashboard; kalau tidak ada, pengguna wajib login ulang.

Inilah pola yang dipakai hampir semua aplikasi nyata: memeriksa sesi di layar pertama, lalu mengarahkan pengguna ke halaman yang tepat. Materi ini melatih tiga hal sekaligus — menyimpan data dengan SharedPreferences, berpindah Activity, dan mengatur alur aplikasi.

Langkah 1–2: Membuat Project & Dua Activity

Langkah 1: Membuat Project

  1. Buka Android Studio → New Project → pilih Empty Views Activity.
  2. Isi Name: SesiLogin, Package name: com.example.sesisilogin, Language: Kotlin, Minimum SDK: API 24.
  3. Klik Finish, lalu jalankan sekali (Run) untuk memastikan project bersih tanpa error.

Langkah 2: Menyiapkan Dua Activity

Project baru hanya punya satu Activity bernama MainActivity. Kita ubah namanya menjadi LoginActivity, lalu menambah satu Activity baru untuk dashboard.

a. Ganti nama MainActivity menjadi LoginActivity

  1. Di panel Project, buka app/java/com.example.sesisilogin/MainActivity.kt.
  2. Klik kanan file tersebut → Refactor → Rename, lalu ganti menjadi LoginActivity. Bila muncul pilihan untuk mengganti nama file layout, centang agar activity_main.xml menjadi activity_login.xml.
  3. Setelah selesai, pastikan isi MainActivity.kt sudah menjadi class LoginActivity : AppCompatActivity(), dan layoutnya bernama activity_login.xml.

b. Tambah Activity untuk dashboard

  1. Klik kanan package com.example.sesisilogin → New → Activity → Empty Views Activity.
  2. Isi Activity Name: DashboardActivity, dan pastikan Layout Name menjadi activity_dashboard (biasanya terisi otomatis).
  3. Biarkan Source Language Kotlin, lalu klik Finish. Android Studio otomatis mendaftarkan Activity ini di Manifest dan membuat file layoutnya.

c. Periksa AndroidManifest.xml

Setelah penambahan Activity, isi Manifest seharusnya seperti ini. Perhatikan bahwa launcher sekarang ada pada LoginActivity — itulah layar pertama yang dibuka saat aplikasi dijalankan.

app/manifests/AndroidManifest.xmlXML
<application
    android:allowBackup="true"
    android:icon="@mipmap/ic_launcher"
    android:label="@string/app_name"
    android:theme="@style/Theme.SesiLogin">

    <!-- layar pertama saat aplikasi dibuka -->
    <activity
        android:name=".LoginActivity"
        android:exported="true">
        <intent-filter>
            <action android:name="android.intent.action.MAIN" />
            <category android:name="android.intent.category.LAUNCHER" />
        </intent-filter>
    </activity>

    <!-- hanya dibuka dari dalam aplikasi -->
    <activity
        android:name=".DashboardActivity"
        android:exported="false" />
</application>
⚠️ Bila Manifest tidak berubah otomatis

Kalau setelah proses rename nama Aktivitas di Manifest masih tertulis .MainActivity, ubah manual menjadi .LoginActivity. Kesalahan satu huruf di sini membuat aplikasi gagal dijalankan (muncul pesan ClassNotFoundException).

Langkah 6: Kelas SessionManager (Ketentuan 3, 9 & 10)

Agar kode baca-tulis sesi tidak tercecer di banyak tempat, kita buat satu kelas khusus bernama SessionManager. Kelas ini yang tahu semua nama kunci dan nama filenya; Activity cukup memanggil fungsinya.

a. Buat file Kotlin baru

Klik kanan package com.example.sesisilogin → New → Kotlin Class/File → pilih Class → beri nama SessionManager.

b. Isi kelasnya

SessionManager.ktKOTLIN
package com.example.sesisilogin

import android.content.Context

class SessionManager(context: Context) {

    // satu objek SharedPreferences dipakai oleh seluruh fungsi di kelas ini
    private val prefs = context.getSharedPreferences(NAMA_PREFS, Context.MODE_PRIVATE)

    companion object {
        private const val NAMA_PREFS = "sesi_login"

        private const val KEY_SUDAH_LOGIN = "sudah_login"
        private const val KEY_NAMA        = "nama"
        private const val KEY_EMAIL       = "email"
        private const val KEY_WAKTU       = "waktu_login"
    }

    // ================= MENYIMPAN SESI =================
    fun simpanSesi(nama: String, email: String, ingatSaya: Boolean) {
        prefs.edit()
            .putBoolean(KEY_SUDAH_LOGIN, ingatSaya)
            .putString(KEY_NAMA, nama)
            .putString(KEY_EMAIL, email)
            .putLong(KEY_WAKTU, System.currentTimeMillis())
            .apply()
    }

    // ================= MEMBACA SESI =================

    // boleh langsung masuk tanpa mengisi form? (diisi oleh centang "Ingat saya")
    fun sudahLogin(): Boolean = prefs.getBoolean(KEY_SUDAH_LOGIN, false)

    // ada data login untuk ditampilkan di dashboard?
    fun adaDataProfil(): Boolean = ambilNama().isNotEmpty() && ambilEmail().isNotEmpty()

    fun ambilNama(): String = prefs.getString(KEY_NAMA, "") ?: ""
    fun ambilEmail(): String = prefs.getString(KEY_EMAIL, "") ?: ""
    fun ambilWaktuLogin(): Long = prefs.getLong(KEY_WAKTU, 0L)

    // ================= MENGHAPUS SESI =================
    fun hapusSesi() {
        prefs.edit().clear().apply()
    }
}

💡 Mengapa ada dua fungsi pemeriksaan?

Keduanya menjawab pertanyaan yang berbeda. sudahLogin() khusus untuk keputusan “boleh langsung masuk atau harus mengisi form?” — nilainya berasal dari centang Ingat saya. Sedangkan adaDataProfil() memeriksa apakah benar ada data login yang bisa ditampilkan; bila tidak ada, dashboard menolak dibuka dan mengembalikan pengguna ke layar login.

Perhatikan bahwa cek sesi belum ada di onCreate di atas — kita tambahkan pada langkah 8. Sekarang fokus ke proses login terlebih dahulu.

LoginActivity.kt - bagian 2: prosesLogin()KOTLIN
private fun prosesLogin() {
    val email = etEmail.text.toString().trim()
    val sandi = etPassword.text.toString()

    // 1) bersihkan pesan kesalahan sebelumnya
    tvPesanMasuk.text = ""

    // 2) validasi isian
    if (email.isEmpty()) {
        etEmail.error = getString(R.string.pesan_email_kosong)
        return
    }
    if (sandi.length < 6) {
        etPassword.error = getString(R.string.pesan_sandi_pendek)
        return
    }

    // 3) cocokkan dengan akun demo
    if (email != EMAIL_DEMO || sandi != SANDI_DEMO) {
        tvPesanMasuk.text = getString(R.string.pesan_login_gagal)
        return
    }

    // 4) susun nama tampilan dari bagian depan email -> "rani" jadi "Rani"
    val nama = email.substringBefore("@").replaceFirstChar { it.uppercase() }

    // 5) SIMPAN SESI. Centang "Ingat saya" menentukan apakah sesi
    //    boleh dipakai lagi saat aplikasi dibuka berikutnya.
    session.simpanSesi(nama, email, cbIngatSaya.isChecked)

    // 6) masuk ke dashboard
    bukaDashboard()
}

private fun bukaDashboard() {
    startActivity(Intent(this, DashboardActivity::class.java))
    finish()   // tutup layar login agar tombol Back tidak kembali ke form
}

📋 Soal akun demo

Pada latihan ini email dan sandi masih hardcode di dalam kode agar mudah diuji. Pada aplikasi sungguhan, proses pencocokan dilakukan oleh server, dan aplikasi hanya menyimpan token hasil login — bukan email dan sandi. Jangan pernah menyimpan sandi di SharedPreferences.

Dashboard hanya menampilkan data — tidak menyimpan apa pun. Nilainya dibaca dari sesi yang sudah tersimpan, lalu ditempelkan ke view.

📋 Mengapa waktunya disimpan sebagai Long?

SharedPreferences tidak mengenal tipe tanggal. Karena itu waktu disimpan sebagai angka milidetik (hasil System.currentTimeMillis()), lalu diubah menjadi tulisan tanggal memakai SimpleDateFormat saat ditampilkan. Cara ini juga membuat waktu mudah dibandingkan bila diperlukan.

Langkah 10: Tombol Logout (Ketentuan 7 & 8)

Logout artinya menghapus seluruh data sesi lalu mengembalikan pengguna ke layar login. Dua langkah itu harus berurutan: hapus dulu, baru pindah layar.

DashboardActivity.kt - bagian 2: keluar()KOTLIN
private fun keluar() {
    // 1) hapus seluruh data sesi dari SharedPreferences
    session.hapusSesi()

    // 2) kembali ke layar login
    kembaliKeLogin()
}

private fun kembaliKeLogin() {
    startActivity(Intent(this, LoginActivity::class.java))
    finish()   // tutup dashboard
}

Logout Lengkap vs Keluar Sebentar

KebutuhanYang dihapusKode
Logout penuh — pengguna harus login ulang dari nol Semua data sesi prefs.edit().clear().apply()

Pada praktikum ini kita memakai logout penuh supaya perilakunya jelas: setelah keluar, tidak ada satu pun data sesi yang tertinggal.

Langkah 12: Checklist Ketentuan & Tugas

Centang setiap ketentuan berikut pada aplikasi Anda. Bila semuanya tercentang, praktikum dinyatakan selesai.

Checklist 10 Ketentuan

  1. Layar login — LoginActivity berisi isian email, isian sandi, checkbox “Ingat saya”, dan tombol Masuk.
  2. Layar dashboard profil — DashboardActivity berisi avatar, nama, email, dan waktu login terakhir.
  3. Data sesi disimpan — login berhasil memanggil simpanSesi() yang menulis ke SharedPreferences dengan apply().
  4. Pemeriksaan sesi — LoginActivity memeriksa sudahLogin() di onCreate() sebelum menampilkan form.
  5. Tanpa data login → login ulang — bila sesi tidak ada atau sudah dihapus, form login tampil dan dashboard tidak bisa dibuka.
  6. Profil tampil dari sesi — nama, email, dan waktu login diambil dari SharedPreferences, bukan dari variabel sementara.
  7. Tombol Logout — tombol Keluar tersedia di dashboard.
  8. Logout menghapus sesi — hapusSesi() menjalankan clear().apply() lalu mengembalikan pengguna ke layar login.
  9. Pilihan “Ingat saya” — nilainya menentukan apakah sesi dipakai lagi pada pembukaan berikutnya.
  10. Satu kelas SessionManager — semua nama kunci dan proses baca-tulis sesi terpusat di kelas ini.

Pengembangan Opsional (nilai tambah)

  1. Layar splash: tampilkan logo 1,5 detik di depan sebelum memeriksa sesi, seperti aplikasi pada umumnya.
  2. Waktu kadaluarsa sesi: simpan batas waktu; bila waktu_login sudah lebih dari 7 hari, paksa login ulang.
  3. Foto profil: tambahkan pilihan avatar seperti pada materi teori, lalu simpan indeksnya di sesi yang sama.
  4. Sapaan waktu: tampilkan “Selamat pagi/siang/malam” sesuai jam perangkat saat dashboard dibuka.
  5. Ingat email saja: saat logout, hapus hanya kunci sudah_login supaya email tetap terisi di form login.
  6. Ganti sandi: tambahkan halaman pengaturan yang menyimpan sandi baru memakai hash sederhana — jangan pernah menyimpan sandi asli.
